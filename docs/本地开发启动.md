# 本地开发启动与停止

本机开发环境由三部分组成：

| 组件 | 地址 | 说明 |
|---|---|---|
| PostgreSQL / Redis | 127.0.0.1:15432 / 127.0.0.1:16379 | Docker 容器 `sub2api-local-postgres`、`sub2api-local-redis` |
| 后端 | http://127.0.0.1:8080 | `backend/bin/server`，配置来自 `backend/.env.local` |
| 前端 | http://localhost:3000 | Vite dev server，`/api` 转发到后端 |

运行时文件（pid、日志）都在 `backend/data/local/`。

## 用脚本

在项目根目录执行：

```bash
scripts/dev.sh start             # 启动容器、后端、前端；已在运行的部分会跳过
scripts/dev.sh stop              # 停止前端和后端，容器保留
scripts/dev.sh stop --with-db    # 连同 PostgreSQL / Redis 容器一起停
scripts/dev.sh restart           # 停止前后端后重新启动
scripts/dev.sh status            # 查看运行状态
scripts/dev.sh logs              # 跟踪后端日志
scripts/dev.sh logs frontend     # 跟踪前端日志
```

可用环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `FRONTEND_HOST` | `127.0.0.1` | 设为 `0.0.0.0` 时局域网也能访问前端 |
| `FRONTEND_PORT` | `3000` | 前端端口 |
| `BACKEND_PORT` | `8080` | 后端端口，需要与 `.env.local` 的 `SERVER_PORT` 一致 |
| `INSTALL_PROXY` | `http://127.0.0.1:7897` | 安装前端依赖时使用的代理 |

`start` 发现 `frontend/node_modules` 不完整时会自动重装依赖；`bin/server` 不存在时会先执行 `make build`。

## 手动执行

```bash
# 1. 数据库
docker start sub2api-local-postgres sub2api-local-redis

# 2. 后端
cd backend
set -a && source .env.local && set +a
./bin/server

# 3. 前端（另开一个终端）
cd frontend
./node_modules/.bin/vite --host 127.0.0.1
```

停止：在对应终端按 `Ctrl+C`，或按端口结束进程：

```bash
kill $(lsof -tiTCP:3000 -sTCP:LISTEN)   # 前端
kill $(lsof -tiTCP:8080 -sTCP:LISTEN)   # 后端
docker stop sub2api-local-postgres sub2api-local-redis
```

## 注意事项

- **不要直接用系统的 `pnpm`。** Homebrew 装的是 pnpm 11，它不读取 `package.json` 里的 `pnpm.overrides`，会认为依赖过期并在 `pnpm run dev` 前自动重装，之前就是这样把 `node_modules` 清空的。项目和 CI 用 pnpm 9，需要时用 `npx -y pnpm@9 ...`。
- **安装依赖要走代理。** 终端直连 `cdn.sheetjs.com` 下载 xlsx 会超时：

  ```bash
  HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897 \
    npx -y pnpm@9 --dir frontend install --frozen-lockfile
  ```

- 修改后端代码后要重新编译：`cd backend && make build`，再执行 `scripts/dev.sh restart`。
