# 首字趋势

入口：**线路优化 → 首字趋势**（/admin/first-token-trend）。

只读看板：按分组（可以再筛到单个号）看使用记录首字的平均、p50、p80 随时间怎么变，同一条时间轴上放同时在跑的请求数、并发上限合计，以及代理、并发上限、号状态的变动，方便对照「什么时候变慢了、那时候改了什么」。本页不改任何号、代理和设置。

「线路优化」下还有「代理优选」，见 [proxy-autoswitch.md](proxy-autoswitch.md)。两边的首字是同一个数、同一套取样。

## 首字口径

只有一种口径：**使用记录首字**，即 `usage_logs.first_token_ms`，和使用记录页显示的一样（含上传请求体的时间）。

| 规则 | 说明 |
|---|---|
| 只算流式请求 | 非流式、`first_token_ms` 为空的请求不进首字统计 |
| 按开始时间分格 | 开始时间 = 完成时间（`created_at`）− `duration_ms` |
| 只算已完成的请求 | 使用记录在请求结束时才写，最近一两格会比实际少一点 |
| 按分组取 | 按 `usage_logs.group_id`；号在别的分组下的请求不算 |

首字 p50 拆段（head / upload / after）是另一套数，从连接 trace（`request_connection_traces`）里的 egress 尝试算，不影响上面的口径。

## 范围和粒度

时间格按北京时间对齐到整格，空格也返回（首字相关字段为 `null`）。

| 范围 | 每格 | 格数 |
|---|---|---|
| 30 分钟（`30m`） | 1 分钟 | 30 |
| 1 小时（`1h`） | 1 分钟 | 60 |
| 2 小时（`2h`，默认） | 2 分钟 | 60 |
| 6 小时（`6h`） | 5 分钟 | 72 |
| 12 小时（`12h`） | 5 分钟 | 144 |

最后一格可能还没走完。页面顶部 6 个数取的是「最近一个完整的格」，箭头和上一格比。

## 自定义时间范围（框选）

在首字趋势图下面的总览条上按住拖动，框出一段时间，页面用 `from` / `to` 重新请求这一段。

| 限制 | 规则 |
|---|---|
| 最短 | 10 分钟，框得更短不发请求 |
| 最长 | 12 小时 |
| 最早 | `from` 不能早于 12 小时前（后端多给 1 分钟误差；前端按「现在 − 12 小时 + 1 分钟」先夹一次） |
| 最晚 | `to` 不能晚于现在 1 分钟；晚于现在的部分截到现在 |
| 粒度 | 按框的长度选：≤ 60 分钟每格 1 分钟，≤ 120 分钟每格 2 分钟，更长每格 5 分钟 |
| 格对齐 | 第一格按北京时间对齐，可能从 `from` 之前开始，这一格只算 `from` 之后的数据 |
| 自动刷新 | 框选期间暂停 |

框选后总览条保留框选前那一整段的数据，点范围按钮或「清除」回到整段。自定义时间段只用 `[from, to)` 里的样本，变动前后的 p50 也不看这段之外的数据。

## 按账号筛

分组旁边有账号下拉，默认「全部账号（不区分）」，整个分组所有号合在一起算。

| 项目 | 说明 |
|---|---|
| 下拉里有哪些号 | 这个分组里所有未删除的号，不管现在筛没筛都给全量。不是 active 或不可调度的号后面标「（不可用）」 |
| 选了一个号 | 首字趋势、6 个数、同时在跑、并发上限合计（只算这个号）、拆段、变动日志、按维度拆开表都只算这个号 |
| 号不在这个分组里或已删除 | 接口返回 400 |
| 切分组 | 账号回到「全部账号」 |
| 框选状态下换号 | 主区按框选的时间段重新请求，总览条也换成这个号的整段 |

按号筛选在 service 层过滤样本，取数的仓储查询还是按分组取（代理优选也复用这套查询）。

## 页面上有什么

| 区块 | 内容 |
|---|---|
| 6 个数 | 最近一个完整格的首字平均、p50、p80、超过 10 秒的占比、同时在跑、样本数；首字类变慢标红、变快标绿 |
| 首字趋势 | 平均 / p50 / p80 三条线（可以单独关，至少留一条），10 秒判慢线，变动竖线（代理、并发上限、号状态三种颜色），悬停看详情 |
| 总览条 | 整段的 p50，用来框选；纵轴压到 40 秒 |
| 同时在跑的请求数 | 每格内请求与这一格重叠的秒数 ÷ 格长（所有已完成请求，含非流式），和并发上限合计（这一刻 active 且可调度的号的并发上限之和）放一起 |
| 首字 p50 拆段 | head、upload、after 三段的 p50，堆叠柱 |
| 变动日志 | 范围内的代理、并发上限、号状态变动，带变动前后各 10 分钟的 p50 和效果（快了 / 慢了多少秒） |
| 按维度拆开 | 按号 / 按代理 / 按模型拆的样本数、平均、p50、p80、超 10 秒占比、同时在跑、小走势图、状态（p50 10 秒以下正常，10–20 秒偏慢，20 秒以上很慢） |

「超过 10 秒」「10 秒判慢线」是看板里写死的 10 秒，和代理优选的阈值配置无关。

页面每 60 秒自动刷新（默认开，可以关），标签页切到后台、正在加载、框选期间暂停。

### 变动从哪来

没有专门的历史表，按下面几处还原：

| 来源 | 还原什么 |
|---|---|
| `audit_logs` | 单号编辑、批量编辑（带 `account_ids` 的）里的 `proxy_id`、`concurrency`、`status`、`schedulable`；开关调度、清错误、恢复状态。审计只存新值，旧值取同一个号上一次已知的值，每个字段第一条只当起点 |
| `proxy_autoswitch_events` | 代理优选换的代理；v1 老记录里的换回 |
| `ops_system_logs` | 认证失败把号标成 error、账号测试返回 401/403、连接错误临时停调度 |
| `account_schedulable_timer_audit` | 定时开关调度实际执行的记录 |
| `accounts.updated_at` | 兜底：号现在是 error 但上面都没记到，按更新时间估一个，detail 里写明 |

建号后 5 分钟内的设置算导入流程，不算变动。限流、过载造成的临时不可调度只在内存和 Redis 里，还原不出来。审计日志没覆盖到范围开头时，`limit_is_current` 为 true，页面提示并发上限按现在的值算。

## 尖峰处理

一根很高的尖峰会把整张图压扁。页面有「压住尖峰」开关（默认开，记在本浏览器里），三张时间图（首字趋势、同时在跑、拆段）都按这个规则定纵轴：

| 项目 | 规则 |
|---|---|
| 纵轴上限 | 当前显示的所有点里排在 95% 位置的值（`floor(0.95 × (n − 1))`）× 1.3，向上取整到 10 |
| 最低 | 首字类 20 秒，同时在跑 10 个 |
| 没有点超过上限 | 按实际最大值显示，不标尖峰 |
| 超出上限的点 | 在图顶画 ▲，图例写「N 个点超出纵轴」；首字趋势里 p80 的 ▲ 旁写实际值（最后一个点除外，右侧已有末值标签） |
| 拆段图 | 按每格三段之和定纵轴，▲ 用最大那一段的颜色 |
| 首字趋势 | 只按当前打开的线算 |
| 关掉开关 | 按最大值显示全貌 |

x 轴刻度：12 小时每小时一个，6 小时每 30 分钟，2 小时每 10 分钟，更短每 5 分钟；窄屏按图宽把间隔放大，保证每个标签至少 56 像素。
## 接口

都在 `/api/v1/admin` 下，需要管理员登录，只读。

| 方法 | 路径 | 参数 | 返回 |
|---|---|---|---|
| GET | `/first-token-trend` | 见下表 | 见下表 |
| GET | `/first-token-trend/groups` | 无 | 数组，所有未删除的分组 `[{id, name}]` |

`/first-token-trend` 的参数：

| 参数 | 默认 | 取值 |
|---|---|---|
| `group_id` | 16 | 正整数；分组不存在返回 404 |
| `account_id` | 不传 = 整个分组 | 正整数；必须在这个分组里且没删除，否则 400 |
| `range` | `2h` | `30m` `1h` `2h` `6h` `12h` |
| `from` `to` | 不传 | RFC3339，必须一起给；给了就忽略 `range`，返回的 `range` 是 `custom`。限制见「自定义时间范围」 |
| `metric` | `usage` | 只能是 `usage` |
| `dimension` | `account` | `account` `proxy` `model`，决定 `rows` 怎么拆 |

取值不对返回 400，带中文说明。查询 10 秒超时。

返回的主要字段：

| 字段 | 说明 |
|---|---|
| `group` | `{id, name}` |
| `account_id` | 筛选的号，没筛为 `null` |
| `accounts` | 下拉用：这个分组所有未删除的号 `[{id, label, status, schedulable}]`，`label` 形如 `#107 名字` |
| `range` `step_seconds` `metric` `dimension` | 实际用的范围、每格秒数、口径、维度 |
| `from` `to` | 实际统计的起止时间（北京时间） |
| `limit_is_current` | 审计日志没覆盖到范围开头，并发上限按现在的值算 |
| `buckets[]` | 每格：`ts` `samples` `avg_ms` `p50_ms` `p80_ms` `over10_pct`（0–100）`head_p50_ms` `upload_p50_ms` `after_p50_ms` `inflight_avg` `concurrency_limit_sum` |
| `rows[]` | 按维度拆：`key` `label` `sub` `samples` `avg_ms` `p50_ms` `p80_ms` `over10_pct` `inflight_avg` `spark[]`（每格 p50），按样本数倒序 |
| `events[]` | 变动：`at` `account_id` `account_name` `type`（`proxy` `concurrency` `status`）`from` `to` `detail` `actor` `source`（`audit` `autoswitch` `system`）`p50_before_ms` `p50_after_ms` |

- `samples` 为 0 的格，首字相关字段都是 `null`；`inflight_avg`、`concurrency_limit_sum` 照样给数。
- `p50_before_ms` / `p50_after_ms` 是这个号变动前后各 10 分钟的 p50；后 10 分钟还没过完时 `p50_after_ms` 为 `null`。
- `status` 事件的 `from` / `to` 只用 `active` `error` `disabled` `schedulable` `unschedulable`。通过管理员 API key 做的改动，`actor` 后面加「（API）」。

## 数据表

没有新表、没有迁移，只读下面这些：

| 表 | 用途 |
|---|---|
| `usage_logs` | 首字样本、同时在跑 |
| `request_connection_traces` | 首字拆段；按代理拆时用 request_id 对出这条请求走的代理 |
| `accounts` `account_groups` `groups` `proxies` | 号、分组、代理名字 |
| `audit_logs` `proxy_autoswitch_events` `ops_system_logs` `account_schedulable_timer_audit` | 还原变动和当时的并发上限、状态 |

## 怎么关、怎么查问题

看板只读，不需要关。不想看可以在侧栏不点它；关掉自动刷新就不会每分钟发请求。

| 现象 | 看什么 |
|---|---|
| 显示「没有数据」 | 这段时间这个分组（或这个号）没有已完成的流式请求；换个范围或分组 |
| 报 400 | 看错误说明：`range` 不对、`from` / `to` 只给了一个、框选不足 10 分钟或超过 12 小时、`from` 早于 12 小时前、号不在分组里 |
| 报 404 | 分组不存在或已删除 |
| 最近一两格的数偏少 | 正常：只算已经完成的请求 |
| 拆段有数，首字没数 | 拆段从 trace 算，首字只算流式请求的使用记录 |
| 并发上限合计和现在不一样 | 按审计日志还原的当时值；看有没有「并发上限按现在的值算」的提示 |
| 改了代理，变动日志里没有 | 建号后 5 分钟内的设置不算；用筛选条件（没写 `account_ids`）的批量编辑还原不出来是哪些号；限流、过载的临时停调度还原不出来 |
| 变动的「后 10 分钟」是空的 | 变动后还没满 10 分钟，或框选的时间段截在变动后 10 分钟之内 |
| 和代理优选的账号监控对不上 | 取样规则一样；代理优选只看当前代理上过去几分钟的 p60 和均值，这里按格看平均、p50、p80，不分代理（选「按代理」拆可以分开看） |
